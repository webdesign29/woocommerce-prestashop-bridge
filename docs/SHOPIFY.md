# Shopify connection (0.8.12)

This is the direct Inklura Sync release, coordinated with the Woo/PrestaShop 0.8.12 pair. Marketplace distribution remains separate. The core catalogue, customer/address and inventory exchanges have been exercised on the demo. Optional ordinary promotion sync and the signed read-only account endpoint have been exercised with the granted discount/app-proxy permissions. Enable them individually and configure the matching app proxy; KerAwen remains the balance authority. Real Shopify orders/payments remain untested because the trial requires a subscription before accepting orders.

The WooCommerce edition can connect one Shopify store independently of its existing PrestaShop partner. It uses Shopify Admin GraphQL API **2026-10**. Shopify queues, source identities, native mappings and cursors use separate `inklura_shopify_*` tables/options. Do not replace the PrestaShop partner webhook with a Shopify URL.

## Configure

1. In Shopify's Dev Dashboard, prepare an app for the store. Use a non-embedded app home pointing to `https://YOUR-WOO-SITE/wp-admin/admin.php?page=inklura-shopify`. Request `read_products,write_products,read_inventory,write_inventory,read_locations,read_customers,write_customers,read_orders`, omitting optional write/customer/order scopes when their features are disabled. Customer data access must be permitted by Shopify. This connector does not require payment, transaction, fulfillment-write or gift-card scopes.
2. Install the app on the intended Shopify store. **Client credentials** authentication is for an app and store in the same Shopify organization. Enter its client ID and secret in **WooCommerce → Shopify Sync**. Tokens are obtained server-side and renewed before their 24-hour expiry. Alternatively configure an existing offline Admin API access token and app secret; externally expired/rotated tokens need replacement. This release does not implement a public-app OAuth installation flow for unrelated merchant organizations.
3. Enter the exact `STORE.myshopify.com` domain. Save in disabled mode, then **Verify connection** to list locations. Select one location, choose directions and optional customer/order imports, then start in **Audit**. Currency and the store-wide tax-inclusive/exclusive price basis must match WooCommerce. Tax rates are not inferred from matching currencies.
4. Configure webhooks using the native admin button. The receiver is `https://YOUR-WOO-SITE/wp-json/inklura-sync/v1/shopify/webhook`. Choose webhook API version 2026-10 in the app. Product/customer/order/inventory notifications are authenticated against the raw body and configured shop, and persisted before acknowledgment. Duplicate delivery IDs are ignored. Records are fetched again from Shopify rather than trusting delivery order or embedded prices.
5. Review the audit queue and switch to **Live** when ready. Live writes also require the existing Sync license to permit live operation. New imported products are drafts unless publication is explicitly enabled. New exported products are always Shopify drafts.

Secrets are native private options with autoload disabled. Secret inputs are never prefilled, secrets are never returned in diagnostics, and blank secret inputs preserve the stored value. Keep database backups protected. A mapped connection's domain/location cannot be changed in place; migrate connection history explicitly. Disabling retains all mappings, jobs and native history. An authenticated app-uninstalled delivery pauses sync and discards the cached access token.

## Supported records

| Record | Behavior |
| --- | --- |
| Products | Import simple/variable products up to 100 variants. Titles, HTML descriptions (sanitized by WordPress), options, SKUs, the primary barcode, regular/sale prices. Imported variant IDs are durable. Linked title/description/SKU/barcode/price/taxable-flag edits can flow back to Shopify. |
| New Woo products | Explicitly export an existing simple or variable product by Woo ID, or opt into automatic creation on save. Unique app-owned Shopify custom IDs allow recovery after lost create responses. Create as a draft, initialize inventory at zero, then transfer the native count through the journalled inventory operation. Optional tag sync follows catalogue direction. Shopify CDN images (up to 20) and collections (up to 100) can be imported additively into native attachments and an isolated category tree. Existing media/category assignments are retained. Wildcard/disabled variations, downloadable-file delivery, weight, tax-rate/class translation, mixed taxable/exempt variants, multi-barcode sets and custom fields are outside this release. |
| Customers | Import registered profiles to customer-role accounts, with generated private passwords and no invitation mail. Never merge by email; a collision stops for identity review. Linked first/last name, email and phone can flow both ways. Shopify default addresses import to Woo billing. A separate address-direction setting enables creation/update of that default address from Woo billing, including recipient names. Other Shopify addresses and Woo shipping are independent. The billing phone maps to the customer primary phone. No password, login session, marketing consent, tax-exemption or balance is exported. Missing source addresses do not clear an existing Woo address. |
| New Woo customers | Explicitly export by Woo ID, or opt into creation on native registration/save. Shopify's unique app-owned source ID is the upsert key; email is never the matching identifier. Staff and mixed-role accounts are rejected. |
| Stock | One selected location, managed whole quantities. A one-sided change flows to the other side. Concurrent differing counts, management changes, parent-shared stock and unavailable location balances stop for review. No aggregation across warehouses and no fractional quantity rounding. |
| Orders | Shopify → native Woo consultation copies with mapped customer/products, exact component checks and matching native tax rates. Custom Shopify statuses display paid/pending/cancelled/refund state without a new payment. Up to 100 product lines and 20 shipping lines. Order access is normally limited to Shopify's standard recent-order window; this release does not request `read_all_orders`. |
| Refunds/financial edits | Refund notifications refresh source status and total-refunded metadata; no refund is executed or invented in Woo. Changed order financial structure, missing/deleted/custom lines and unmatched tax components require review. Native line identities/history are preserved. |

Shopify product/customer imports become native Woo records and can be captured by the existing Woo/PrestaShop pair under its own native-customer, tax, conflict and license settings. Shopify order consultation copies are excluded from that pair so they cannot enroll as new Woo-source KerAwen financial orders. A direct Shopify/PrestaShop connector, Woo-order export, fulfillment actions, shared Shopify/KerAwen gift-card/store-credit/loyalty checkout are not implemented by this release.

## Recovery and operations

- Webhooks do no Shopify API work before acknowledgment. A worker fetches bounded pages of each enabled resource and retains independent cursors to recover missed notifications. Unchanged source timestamps/native profiles do not create repeated jobs; a six-hour product sweep additionally checks inventory. Old failed/conflicting jobs block newer jobs for that resource; other resources continue.
- Local change hooks enqueue mapped records. Optional native creation hooks are opt-in. Manual retry keeps all identity and conflict checks. Deletion notifications require review and never delete native accounts/products.
- Incoming native writes and local mapping/baseline changes share a database transaction. Inventory pulls lock the native stock row and compare its current count. Outgoing inventory writes use `inventorySetQuantities` with `changeFromQuantity`, an event-specific `@idempotent` key and a persisted intent containing the original arguments. Lost responses replay that key before advancing the baseline. Incomplete intents older than 23 hours require review instead of making a fresh potentially duplicate adjustment. Catalogue/customer write ambiguities or simultaneous edits can require profile review; no unsafe last-writer override is provided.
- New source records use an app-owned `id` metafield definition and lookup-before-create. A create timeout can be recovered by source ID without creating another product/customer. Identity or content changes during recovery require review.
- The regular WP-Cron minute hook runs the Shopify worker. The Woo server CLI `--command=tick` also runs it after the existing pair. Dedicated commands:

```sh
php includes/worker-cli.php --root=/absolute/wordpress --platform=woo --command=shopify-tick
php includes/worker-cli.php --root=/absolute/wordpress --platform=woo --command=shopify-health
```

- The admin queue and worker show internal diagnostic codes only. Rate limits/transient network failures use bounded backoff. A conflict is a request for a data/identity decision, not permission to overwrite native payment/history.

## Validation

`php tests/shopify.php` exercises domain/GID validation, raw-body HMAC, settings, scope-free transport error handling, current token renewal, decimal quantities and concurrent-change decisions. `tests/shopify-native.php` refuses all databases except `wd29woo` at `woo.example.test`; it runs real WooCommerce and InnoDB operations with an injected Shopify API emulator. Run both HPOS and legacy fixtures. The emulator is not evidence that Shopify has accepted the app scopes/schema or that live webhooks have been delivered; record live acceptance separately after installing the app.

API contracts: [Shopify authentication](https://shopify.dev/docs/apps/build/authentication-authorization), [inventory comparison and idempotency](https://shopify.dev/docs/api/admin-graphql/latest/mutations/inventorySetQuantities), [webhook verification](https://shopify.dev/docs/apps/build/webhooks/verify-deliveries), [unique source IDs](https://shopify.dev/docs/apps/build/metafields/working-with-custom-ids).

New optional features default off on an existing connection. Address export requires both customer and address directions to permit writes. Incomplete addresses stop for review. Existing legacy address baselines do not silently accept recipient-name edits. Shopify may normalize address fields; unequal results require review. Image downloads permit only HTTPS cdn.shopify.com /s/files/ URLs, pin public IPs, reject redirects and enforce MIME, dimensions and byte limits. Image and collection imports never delete attachments or terms.

## Optional promotion codes

Enable `coupons` and select their direction only after granting `read_discounts` (and `write_discounts` for both directions). Configure the three discount webhooks with the native button. Manual coupon export accepts a Woo coupon ID; automatic export is a separate opt-in. API version 2026-10 retains the code-discount queries used here.

Supported rules are ordinary single-code promotions available to all customers and all products, with no usage limit or per-customer quota, no minimum/maximum/exclusions/subscription entitlement, and no combination with another discount. Percent, fixed cart and fixed per-item amounts map to native Woo types. Expiry is preserved. Future Shopify starts are deferred and a previously active mapped copy is suspended until the start. Updated signed notifications wake a stale scheduled wait.

Unsupported or deleted source rules suspend their native copy, preserving coupon/history. If the held copy has not been edited, fixing the source and retrying can restore it. Unsupported native restrictions suspend the native coupon and deactivate its linked Shopify discount in both-direction mode; fixing the native rule and publishing/retrying retains the verified remote baseline. A concurrent edit requires review. Coupon code collisions never merge identities, including native draft/trash records. Creation writes a random provenance tag in its persisted intent before HTTP; a lost response can be recovered by code only when that tag and complete supported contents match.

KerAwen-origin vouchers and consumable shared quotas cannot be exported as independent promotions. Shopify automatic discounts, BXGY, shipping discounts, customer/product-specific rules, minimums and stacking require explicit translation and are held instead of approximated. Native Commerce Pro can transport an ordinary imported Woo promotion to PrestaShop under its own settings; it remains an unlimited promotion, with no shared wallet claim.

## Read-only KerAwen account on Shopify

Requires Commerce Pro with its authoritative account reader, a live licensed Woo/PrestaShop connection with native customer linking, and an existing exact Shopify-to-Woo customer mapping. Enable `account_proxy` and request `write_app_proxy` in the app. In the Shopify app version, set prefix `apps`, subpath `inklura-benefits`, upstream `https://YOUR-WOO-SITE/wp-json/inklura-sync/v1/shopify/account`. The native path setting must match `/apps/inklura-benefits`; other supported Shopify proxy prefixes can be configured explicitly.

The page at `https://STORE.myshopify.com/apps/inklura-benefits` verifies Shopify's raw-query HMAC with repeated-query handling, rejects duplicate subject/auth fields, pins the configured shop/path and accepts timestamps within five minutes. Only the signed logged-in customer ID can select the account. Unmapped, disabled, privileged/mixed-role, rebound or ambiguous native customer identities cannot read benefits. The existing signed peer reader supplies current KerAwen points and available rules; no separate balance is stored. Responses use no-store headers and escaped ordinary HTML rather than Liquid. Anonymous signed requests display a login prompt; direct unsigned requests reveal no balances.

This page provides account consultation. It does not make KerAwen gift cards, credit or loyalty spendable at Shopify checkout. Private-app Shopify Functions and checkout integrations have platform/plan constraints; an atomic authority-backed spending workflow must be implemented before enabling redemption.

## Shipping requirements and source order history

New imported/exported variants preserve Shopify `inventoryItem.requiresShipping` as the Woo virtual flag. Non-downloadable services can therefore be created correctly as drafts. Enable `shipping_flags` to reconcile mapped flag edits in the catalogue direction. Its independent baseline avoids changing old catalogue hashes; an old mismatched field with no baseline requires review. Downloadable file delivery is not exported. Shopify gift-card products, subscription-only products and component bundles are held rather than converted into ordinary merchandise. If Commerce Pro gift-card features are active, new Woo exports also check the KerAwen native product flags; unavailable authority defers creation, and gift products require a proper authority-backed workflow.

Enable `order_details` with order import to retain source fulfillment/tracking, refund summaries and transaction status in the Woo admin. This is a separate projection, preserving existing order financial hashes. It supports up to ten fulfillments (ten tracking entries each), ten refunds and fifty transactions, and requires review instead of truncating larger histories. Source IDs cannot disappear and native consultation history edits require review. Native payments, WC refunds and stock are unchanged by this projection. The current demo trial still prevents live order creation without a paid subscription; native order/history behavior is tested in the isolated Woo/MySQL fixtures.

## Photos on new Woo exports

Enable `export_media` separately to include the native featured image and product gallery when creating a new Shopify product (up to 20 public JPEG/PNG/WebP uploads, 10 MiB and 40 megapixels per image). Only HTTPS files under this Woo site’s own uploads URL and directory are accepted; private, signed, external-CDN and non-image attachments require review. Variant-specific media and subsequent gallery edits are outside this option. Existing mapped Shopify galleries are retained.

The initial export snapshot includes attachment IDs, file hashes, public URLs and alt text. Unique product custom IDs recover lost creation replies; deterministic file names reject collisions. The connector waits for Shopify processing before adopting the product, requires review on failed/ambiguous images or a changed native snapshot, and registers image references so the optional subsequent Shopify import reuses the original Woo attachments. Images must remain publicly fetchable by Shopify.
